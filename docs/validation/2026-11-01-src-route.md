## Preparation contract

The private extractor accepts exactly three graph nodes and two edges:
`VirtualPlayback -> Bus -> VirtualMicrophone`. It requires one Bus input,
matching mono/stereo widths, distinct virtual endpoint IDs, default unity
post-fader sends, identity initial strips and no desired parameter intents.
It validates the project and the backend's supported rates/block bounds.
Extra nodes, side routes, unused Bus inputs, other input/output kinds, modified
sends/strips or unsupported configurations produce no witness. They do not
reject otherwise usable audio projects.

`PreparedSrcRoute` retains source/Bus/sink identities, both configured virtual
endpoint IDs, channels, Engine rate/block and the exact **prepared graph
revision** from the backend request. Endpoint IDs use the existing32-lowercase-
hex serialization; they are not Windows endpoint or driver-handle evidence.
The public read handle's `src_route()` pins these facts to its original owner.
The general observation snapshot DTO is unchanged to avoid unrelated app/UI
literal changes.

A sticky atomic flag is set on that owner's compatible Update preparation,
before validation/cancellation checks. This is deliberately conservative:
failed or cancelled candidates may invalidate unnecessarily. Generation
mismatch cannot invalidate another retained owner, and registry replacement
cannot redirect an old handle. Invalidation retains all original facts and
never promotes candidate topology to active topology.

**Even `invalidated=false` is not active-plan evidence.** Initial publication
precedes successful activation; live parameter changes can bypass backend
preparation; the flag and callback histories are not a shared transaction.
There is no callback-aligned active plan revision or control history here.
A caller cannot use this witness alone to infer continuous unity routing,
clean upstream audio, a composed FIR center or a native time reference.

All route extraction, allocation, cloning, invalidation and publication run
on control paths. The existing bounded RT histories and audio code are not
modified. The shared route state is fixed-size, with no lifetime route log.

## Archive and independent readback

New `NativeSrcTrace` artifacts use trace schema3 with a `route` observation.
Collectors preserve immutable preparation and accumulate invalidation during
poll/finalization. Finalized artifacts remain frozen; calling finish while
writers are still open keeps the existing refusal rather than claiming closure.
Outer summary schema2, chunk schema1 and checkpoint schema1 remain unchanged.
Older tools that only support trace2 must refuse trace3 rather than ignore it.

The independent reader supports both trace2 and trace3. Trace2 reports unknown
route without inventing one. Trace3 validates strict route fields/types,
distinct identities, exact source/playback and sink/microphone boundary linkage,
endpoint encoding, channels and supported Engine rate/block. Callback rates
must agree and callback frame counts must fit the prepared maximum. Exact
terminal metadata agreement includes the invalidation flag and original route.
No matching labels authenticate imported origin.

Reader statuses are `unknown`, `imported_preparation_only` and
`invalidated_preparation`. Route invalidation/absence is independent of scalar
coverage and never erases collection refusals. All existing byte/work caps,
create-new outputs and complete-stream/terminal checks remain. Every report
keeps `qualified=false`, `native_execution=false`, unknown source origin and
unevaluated waveform/physical delay. Phase mapping still means local FIR
arithmetic only; no cascade mapping is enabled.
