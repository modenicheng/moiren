# W00：软件设备 PnP 生命周期与权限

日期：2026-10-08。用户确认没有支持动态音频 endpoint 的已签名 INF 包，选择先完成 PnP 生命周期与权限测试。以下结果属于通用软件设备节点，不计为动态音频 endpoint 或 W15 完整验收。

## 环境、探针与证据

- Windows 11 x64 build 26300，沿用[同日环境记录](2026-10-08-environment.json)。QQMusic.exe PID 33356，FreeDSP 为全部 render / capture 默认角色；QQMusic session 为 active、volume 0.4、muted false。
- 独立 `w00_swdevice` example 使用固定 `MoirenW00` enumerator、每个场景一个 GUID instance，parent 为 `HTREE\ROOT\0`。Hardware ID 为 `Moiren\W00NoDriver`，compatible ID 为 `Moiren\W00Probe`；未提供音频驱动包。
- 两种场景都使用 Removable、SilentInstall、NoDisplayInUI；第二种另加 DriverRequired。默认 Handle lifetime 经 GetLifetime 确认，并显式 SetLifetime(Handle)。没有启用 ParentPresent。
- 普通权限直接运行已编译 executable；管理员通过 Windows UAC 运行相同 executable。JSON 在资源关闭、精确卸载后写出。探针没有操作其他设备或驱动包，没有打开 PCM stream 或保存音频。
- [普通权限报告](2026-10-08-swdevice-user.json)、[管理员报告](2026-10-08-swdevice-admin.json)保留每次 HRESULT / CONFIGRET、callback identity、PnP / INF 状态和音频目录快照；[清理与驱动对照](2026-10-08-swdevice-verification.json)保存全部 MEDIA 驱动前后对照、遗留实例数与独立断言结果。原始文件也保留在 `target/w00/`。

## 实测结果

| 项目 | 普通权限 | 管理员 raw node（3 轮） | 管理员 DriverRequired（3 轮） |
|---|---|---|---|
| TokenIsElevated | false | true | true |
| SwDeviceCreate | `0x80070005`，未获 handle | 成功并收到 callback | 成功并收到 callback |
| callback CreateResult | 无 | 每轮 `S_OK` | 每轮 `S_OK` |
| 已打开 handle 时同 ID 再 create | 未执行 | 每轮 `0x800700B7` | 每轮 `0x800700B7` |
| 默认 lifetime | 未执行 | 0 / Handle | 0 / Handle |
| present 查询 | 未执行 | `CR_SUCCESS` | `CR_SUCCESS` |
| problem code | 未执行 | 0 | 28 |
| bound INF | 未执行 | Windows inbox `c_swdevice.inf` | 无；property query `0x25` |
| close 后 NORMAL locate | 未执行 | `CR_NO_SUCH_DEVNODE` / `0x0D` | 同左 |
| close 后 PHANTOM locate | 未执行 | `CR_SUCCESS`，实例记录保留 | 同左 |
| DiUninstallDevice 精确实例卸载 | 未执行 | 每轮成功，NeedReboot=false | 同左 |
| 卸载后 PHANTOM locate | 未执行 | `CR_NO_SUCH_DEVNODE` / `0x0D` | 同左 |
| 新增 / 消失 audio endpoint | 0 / 0 | 每轮 0 / 0 | 每轮 0 / 0 |

管理员两个场景各使用同一个 identity 重复三轮；**每轮都先完成卸载，再开始下一次 create**。这没有测试 close 后保留 phantom、跳过卸载直接重新创建或 API 在前次 removal 未完成时排队的行为。

重要区分：DriverRequired 节点的 callback 成功只表明 PnP 枚举成功；problem code 28 和缺少 INF 表明没有匹配驱动。raw node 的 inbox 通用绑定也不是音频能力证据。本次所有状态的 audio endpoint ID 仍为原来的 68 个；没有新增可供外部应用选择的 playback / microphone。

close 后 PHANTOM locate 成功，但 `CM_Get_DevNode_Status` 返回 `0x0D`；报告没有把 phantom 实例称为 present 或丢弃这个原始返回值。`SwDeviceClose` 会发起移除并保证返回后不再调用创建 callback，但不等待 PnP 移除全部完成，也不卸载持久实例；本次轮询和精确卸载验证了这一区别。[SwDeviceClose](https://learn.microsoft.com/en-us/windows/win32/api/swdevice/nf-swdevice-swdeviceclose)

## 状态与清理

- 普通 / 管理员运行前后 all-state audio endpoint ID 完全一致；管理员创建期间六次对照均无新增或消失。active endpoint 为 8 个，全部 endpoint 读取无错误。
- 六个默认角色、endpoint volume / mute、QQMusic 同一 session 的 volume / mute 前后一致；QQMusic 仍为 PID 33356、active、0.4、unmuted，目标 session 读取无错误。其他两个 system session 的 process identity 查询返回 `0x8007001F`，不用于判断 QQMusic 状态。
- 独立 `Get-PnpDevice` 全状态查询在结束时未发现任何 `SWD\MoirenW00\*` 实例，包括 phantom。全部 MEDIA 驱动 DeviceID、INF、version、IsSigned 前后一致。没有要求重启。
- 状态快照一致不证明期间不存在短暂可听影响；本次探针没有打开音频流或修改播放设置。

## 复现与范围

命令和 UAC 入口见 [crate README](../../../crates/moiren-windows-audio/README.md#software-device-lifecycle-and-privileges)，步骤见[实施计划](../../plans/2026-10-08-w00-swdevice-plan.md)。普通权限运行的 exit 1 是预期拒绝结果，必须检查报告中的 `permission_denied` / `0x80070005`；管理员运行 exit 0，六个 cycle 均为 completed。

`SwDeviceCreate` 的管理员要求和异步 callback 契约见[官方文档](https://learn.microsoft.com/en-us/windows/win32/api/swdevice/nf-swdevice-swdevicecreate)。本次 `DiUninstallDevice` 只删除本次节点实例，不是删除驱动包；其行为及 NeedReboot 见[官方文档](https://learn.microsoft.com/en-us/windows/win32/api/newdev/nf-newdev-diuninstalldevice)。基于实测可确认：管理器不能仅用 create 同步返回值宣称设备可用，也不能用 close 返回值宣称持久实例已经卸载。

未测试：真实动态音频 endpoint、PCM transport、外部应用持有音频 endpoint 时删除、INF 安装 / 升级 / 驱动包卸载、签名与回滚、强制终止进程、ParentPresent、普通权限卸载已有测试节点，以及产品级特权 helper / IPC。

范围收敛前的既有 VB-Audio 对照另外发现：CABLE 两个 render 的 1 秒静音探针可完成，CABLE Output capture 的用户态探针以 `0xC0000005` 退出、未输出报告（`target/w00/2026-10-08-vad-single-exits.json`）。尚未定位原因，不能归为该驱动不支持。本轮按用户指定转向 PnP 后不继续诊断；VB-Audio 未安装、升级或卸载。

验证：`cargo fmt -p moiren-windows-audio --check`、package all-targets check、22 项测试、all-targets Clippy `-D warnings`。实机与纯测试分别记录，不依赖普通 `cargo test` 自动提权。
