# W00 首轮：QQMusic 被动捕获

日期：2026-10-08。范围：设备 / session 快照与指定进程树捕获。结果：在本机 QQMusic 正常播放时取得非零音频统计并正常停止；W00 其余场景未完成。

## 条件与证据

- Windows 11 专业版 x64，build 26300；Intel Core Ultra 9 285H；Performance 电源方案。
- 活跃 endpoint：5 个 render、3 个 capture，包含 Realtek、FreeDSP USB 耳麦、显示器音频和 VB-Audio Virtual Cable。虚拟 endpoint 不作为独立物理时钟证据。
- QQMusic.exe：本次 PID 33356，创建时间 `134358997085309393`（Windows FILETIME，100 ns）；通过“耳机 (5- FreeDSP)”播放。PID 是实验身份，复现时须重新查询。
- FreeDSP 对应 Microsoft USB Audio 2.0 driver `10.0.26100.9457`，`usbaudio2.inf`；Realtek driver `6.0.9802.1`。增强 / spatial 设置与硬件实际格式未读取，记为 Unknown。
- [环境与驱动记录](2026-10-08-environment.json)、[首次目录快照](2026-10-08-catalog.json)、[60 秒统计与前后快照](2026-10-08-qqmusic-60s.json)。
- 完整 5,998 行 packet 元数据在本机 `target/w00/2026-10-08-qqmusic-60s.json`。原始 trace 保持在 Cargo 已忽略的 target 内；仓库中的 JSON 保留汇总与前后快照，不包含 PCM。

## 步骤

1. 保持 QQMusic 按用户原设置播放，读取当前 PID。
2. `cargo run -p moiren-windows-audio --example w00_probe --locked -- --list`，枚举 active capture / render endpoint 与 render session。
3. `cargo run -p moiren-windows-audio --example w00_probe --locked -- --pid 33356 --seconds 60`。请求 include target process tree、Shared、48 kHz / stereo / f32，并启用 Windows 自动格式转换。
4. 每个 capture packet 在有效 buffer lease 内统计，完整 Release；只写预分配元数据，不回放音频。到期停止、释放 COM / stream，再写 JSON 和读取后快照。
5. 比较默认角色、endpoint 音量 / mute 和 QQMusic session 音量 / mute。

## 实现问题与修正

首个 60 秒尝试及随后的 1 秒定位运行在 activation 返回前出现 `0xC0000374`（heap corruption），没有取得有效采集报告。定位到 `windows 0.62.2` 的 `PROPVARIANT` 实现自动 Drop / `PropVariantClear`：activation BLOB 指向 Arc 管理的 Rust 内存，外层 variant 原先会自动析构，触发错误释放。

修正为外层 `ManuallyDrop<PROPVARIANT>`，仅借用参数；callback 持有参数 Arc，覆盖迟到 completion。加入 BLOB 不释放 Rust 存储和 agile callback 最后引用生命周期的两个回归测试。修正后 1 秒 smoke 捕获（97 packets）与本次 60 秒运行均成功。此次失败属于探针实现问题，不记为平台能力不支持。

## 结论与未测范围

- **已实测支持（限定本机）：**active endpoint / session 查询；显式 PID 的 Process Loopback 激活、48 kHz stereo f32 非零信号采集、60 秒有界运行、正常 Stop；前后播放设置没有观测到变化。
- **需要指定条件：**本次 process loopback device position 恒为 0。它不能作为物理设备 sample position；后续 W01 / W09 必须探测各 capture 模式的时间戳能力，不根据错误 flag 缺席直接推导时钟可用。
- **未测：**独立对照信号、include / exclude 比较和进程隔离、浏览器子进程、重启 / PID 复用、OBS 并行捕获、mute / volume 对信号的影响、Takeover、exclusive / DRM、普通 endpoint loopback、物理 capture、Shared render、双 endpoint / 跨钟、断连恢复与 30 分钟 / 2 小时运行。
- **结果无法判定：**听感是否完全无影响、捕获内容是否只包含 QQMusic；未录音试听，也没有无关应用信号的独立对照。
- **已知不支持：**本次没有足够证据新增此类结论。

下一项建议：保留 QQMusic 播放设置，增加可识别的独立对照信号或 include / exclude 比较，验证捕获范围；会产生额外播放声音的实验应另行安排，不在本轮自动执行。
