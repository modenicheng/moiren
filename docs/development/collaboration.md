# 协作、决策与代理编排

本文记录与用户协作、做设计决策、派代理干活的稳定约定；具体规则本身见 [README.md](README.md) 索引。

## 用户偏好

- **语言与风格**：中文沟通，信息密度高、直接；先给结论和证据，再展开。不要用含糊的"应该/大概"。
- **追根因**：说某个设计"不好/要移除"时，先判断该功能是否属于这个界面的职责，再追底层模型；不要只给改文案/局部合并的保留式方案。方案按"切多深"分层（页面 / UI 状态 / service 模型）让用户选。
- **做减法**：倾向彻底删除、不保留不干不净的改动；反防御性编程，但实时/数据安全边界不省。
- **数据真实性**：UI 不画假数据，Unknown 用 `—`；候选配置与活动配置、Accepted 与 Applied 不混用。
- **详细参数可配置**：出现在 Inspector/详细控制面的技术参数（编码参数、缓冲、格式等）必须用户可调；默认值只做默认，不替用户决定。
- **术语**：音频行话简称（M/S、MONO、SWAP、DIM 等）所有语言保持英文，不汉化。
- **精确执行**：用户对设计元素/选择器/文案的批注按字面执行，不换邻居、不扩大范围；拿不准先问。
- **保护现场**：不要动用户正在改的 WIP；不要修改 `.git/`；并行会话要每次重查分支与状态。
- **机器负载**：实现阶段避免高并行重命令；测试/编译优先远端，本地降并发（`-j 2`/`-j 4`）。长任务异步化，不要阻塞回合等 CI。

## 决策协议

- 有多个合理方案或需要取舍时，用带推荐项的提问让用户拍板，不要静默选一个。
- 决策编号（D-1、D-2……）写进计划/设计/[docs/TODO.md](../TODO.md)；设计文档里把"用户裁决"逐条列出（编号 + 结论 + 日期）。
- 放弃/不做也有记录：写 `resolved-wontfix` 与理由，不静默删除。
- 用户已经拍板的方向视为约束；后续实现发现冲突时，先指出冲突再请求重新裁决。

## 独立审计

- 深层 bug、架构疑问、修复代价高的问题：**先只读审计，后改代码**。派独立代理，给足证据、约束与假设，要求 proven / high-confidence / unverified 分级 + 修复契约（先不写代码）。
- 全仓审计常用"每部分 2 名独立初审 + 1 名独立复核 + 主代理汇总"；并发上限按机器负载控制在 2–6，报告写文件防中断丢失。
- 审计结论可互相印证也可互相矛盾；矛盾项由主代理亲证裁决，并在 README/复核报告中记录改判理由。
- 审计报告、整改批次、修复率对账遵循 [documentation.md](documentation.md) 的审计格式。

## 代理编排

- **计划先行**：先产计划（范围/决策/阶段/验证门/风险/量化），用户确认后再分派实施。
- **拆分与并发**：按工作包拆分互不重叠的文件/模块，每个子代理明确写作用域与验收标准；重编译/测试任务串行或放到远端，不要多个 cargo 同时压本机。
- **写文件防丢**：子代理把 brief/context/report/review/命令日志落到 `.superpowers/sdd/` 或 `.zcode/` 一类本地目录，主代理只汇总结论。
- **异步与续跑**：CI、合并、长测试放后台（日志 + 哨兵），不阻塞回合；子代理撞配额/中断时先保存增量，再续跑。
- **回收**：战役结束后清理 worktree/分支，更新本地记忆（见 [documentation.md](documentation.md)），把稳定规则回填到仓库文档。

## 汇报与边界

- 汇报用中文，结构固定：**现在完成了什么 → 证据 → 未完成/待用户执行 → 风险与需要拍板的点**。不要用"已全部完成"掩盖未跑的验证。
- 遇到网络、权限、硬件、代理等环境问题：说明现象与已尝试的绕法，不擅自改用户的系统配置；恢复后从中断处继续。
- 不代替用户做硬件/听感/性能验收结论；涉及真实设备的操作（安装驱动、切换默认设备、播放测试音）由用户执行。
- 密钥、令牌、内网凭据不入库、不写进文档；审计报告必需引用时做占位符脱敏。
