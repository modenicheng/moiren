# 协作、决策与代理编排

本文管可公开的协作规则；个人偏好、机器负载与汇报习惯属于本地信息，放在未跟踪的 `local/preferences.md`（若存在，先读它；模板见 [local.example.md](local.example.md)）。

## 通用协作原则

- 结论先行、证据优先；不确定时列出假设并提问。
- 用户已确认的要求是约束；实现发现冲突时先指出再请求裁决。
- 有多个合理方案时用带推荐项的提问让用户拍板，不要静默选一个。
- 决策编号（D-1、D-2……）写进计划/设计/[docs/TODO.md](../TODO.md)；放弃项写 `resolved-wontfix` 与理由。
- 不代替用户做硬件/听感/性能验收结论；真实设备操作由用户执行。
- 密钥、令牌、内网凭据、个人机器信息不入库、不进公开文档；需要引用时用占位符。

## 独立审计

- 深层 bug/架构疑问/高代价修复：**先只读审计，后改代码**。派独立代理，给足证据、约束与假设，要求 proven / high-confidence / unverified 分级 + 修复契约（先不写代码）。
- 全仓审计常用"每部分 2 名独立初审 + 1 名独立复核 + 主代理汇总"；并发按本地机器负载控制，报告写文件防中断丢失。
- 审计结论可互相印证也可互相矛盾；矛盾项由主代理亲证裁决，并记录改判理由。
- 审计格式与整改流程见 [documentation.md](documentation.md)。

## 代理编排

- **计划先行**：先产计划（范围/决策/阶段/验证门/风险/量化），确认后再分派实施。
- **拆分与并发**：按工作包拆分互不重叠的文件/模块；每个子代理明确写作用域与验收标准。重编译/测试任务串行或按本地环境说明转移，不要并发压满本机。
- **写文件防丢**：子代理把 brief/context/report/review/命令日志落到本地未跟踪目录，主代理只汇总结论。
- **异步与续跑**：CI、合并、长测试放后台（日志 + 哨兵），不阻塞回合；中断时先保存增量再续跑。
- **回收**：战役结束后清理 worktree/分支，更新本地记忆；稳定、可共享的规则回填仓库文档。

## 汇报与边界

- 汇报结构：**完成了什么 → 证据 → 未完成/待用户执行 → 风险与需要拍板的点**。
- 不把未跑的验证说成完成；明确区分便携测试、CI 与实机验收。
- 遇到网络、权限、硬件、代理等环境问题：说明现象与已尝试的绕法，不擅自改用户系统配置；恢复后从中断处继续。
